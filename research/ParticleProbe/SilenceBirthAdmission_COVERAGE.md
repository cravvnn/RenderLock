# Silence birth admission

This integrates the immutable `SilenceBirthInputs.Qualify` predicate into the
current `ReplayEventTimeline.Parse` and helper dispatch. The original CREATE3,
separate CP0 mode1, finite recorded and observed fallback values, model identity
and old2007/5d5 profile remain explicit. Other creation/world/snapshot fields
refuse even if null. Missing header never enables mode3. No native pin is widened.

The new timeline property is a cloned immutable JsonElement. There is no writer,
cache, cursor, process, inferred reset or asynchronous owner in this predicate.
The model describes its caller protocol: qualify the header, validate original
creation/literal history and independent hitbox frames, simulate inclusive frames,
then acknowledge exactly that header. Failures remain fatal to this helper result.
Pure field/type/math guards are exercised by compiled retained-packet cases.
`HitboxRuntimeInputs`/`HitboxFrameHistory` model the installed shape cursor and
consumer clocks independently; they are not inferred from a birth observation.

Simplification: use a local `observedModeThree` fact derived from already validated
Crossbow/Silence inputs. Do not copy the old generic creation wrapper or store a
second creation-mode state. Snapshot, world, existing literal handling and normal
output without Silence input keep their current contracts. The material build
rejects Silence headers explicitly and does not compile these new classes.

The response adds birth and root-position acknowledgements only for the qualified
Silence branch. An empty root-position summary or missing authored controls still
fails Python's existing exact v4 response gate. Current root CP3/4 writers are
not implemented/qualified by this change. Neither an admitted birth nor a cloned
acknowledgement proves valid full-effect output, current engine capture, independent
child/model selection, fresh rig acquisition, saved scenes or Cycles rendering.
The historical broad Silence model was deliberately not copied: it described
additional source-epoch/loading/rendering integration that is absent here.

Actual retained-request diagnostic: the helper reaches all157 frames and returns
the original birth/header bindings unchanged, then exits with unsupported scalar
warp warning. Root-position acknowledgement is empty; CP3/4 remain unprovided
under the old v2 policy. Python's existing strict response validator refuses this
result. This confirms the remaining root-writer/scalar-warp gates directly; no
diagnostic output is promoted to a supported effect or normal-export success.
