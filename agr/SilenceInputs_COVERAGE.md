# Silence creation/body-selection and hitbox inputs

These components are synchronous immutable validation/transformation functions.
They introduce no process, cache, retry, file writer or persistent cursor, so no
new lifecycle model is needed. Existing helper hitbox-history/cursor protocols
are independent obligations and have not been ported or newly qualified here.
The normal recorded-effect dispatcher does not yet acquire/use these inputs.

The birth packet keeps the exact old2007/5d5module pair, finite recorded AND
observed fallback values, flags0, unit owner SRT, CP0 mode1/identity matrix and
unchanged recorded CREATE3. Child selection is a separate old6a7/other explicitly
qualified legacy graph profile with no eligible render child. One observation
does not establish another, hitboxes, a current native reader or effect lifetime.
The frozen legacy scene fingerprint retains replay/events/rig/pose and optional
network-projectile inputs; the generic current scene identity is unchanged.
Neither old packet is rehashed/rebound to force fresh-scene admission.

The Silence-only control plan admits recorded owner-originCP0, parent-body named
attachmentCP1 and original literalCP2, with independently checked birth and
child packets. The four exact definition hashes remain mandatory. No generic
Crossbow birth override, Sprint/custom-origin capture or old cross-effect
admission wrapper is ported. Custom-origin matrix multiplication is pure reused
math for validating the explicit unit SRT; it does not register that provider.

Hitbox preparation requires exact model/bone order, owner, integer tick andCP0.
Selected boxes/capsules/spheres use authored bounds and actual supplied uniform
bone transforms. Unselected bone rows can be explicitly unavailable; a selected
missing, Boolean or nonfinite row refuses. No root-bone or identity fallback.
Dense frame additions have limits of10000ticks,128sets,4096boxes/set and200000
total records. They are not a complete simulation/control-point plan and do not
acquire poses. Headers stay fixed across frames, binding model/source/bone order.

The generic prepared-package validator now requires both Silence packets, exact
hitbox/provider identities and helper acknowledgements, including recordedCP0/1/2,
authored-rootCP3/4 and no unprovided points. Only this fully validated profile may
use authored-root-position-v4 without changing global control-point policy. Null
snapshot tags from its known response are not treated as Crossbow input; non-null
or mixed creation/snapshot providers refuse. Every non-Silence Crossbow gate is
unchanged. A valid input package still faces the independent static geometry,
material, rope/shader and runtime rendering gates before any success claim.

Simplification: reuse frozen identity, existing record compilation and typed
model/pose metadata; add one narrow Silence validator instead of importing the
old generic creation wrapper or relaxing current Crossbow. No code searches an
entity list for a substitute model, guesses a hitbox, changes recorded events or
infers empty history/lifetime. Hashes detect inconsistent bytes, not edited-data
authenticity. Actual retained-packet admission/request reconstruction is input
proof only; current helper integration, fresh rig/pose acquisition, normal export,
actual Blender/save/rollback and Cycles remain pending.
