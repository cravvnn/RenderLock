# Captured slide material parameter projection

`particle_slide_parameters.resolve_slide_artist_values` is one pure computation
over explicit captured data. It has no process, file, cache, queue, retry, Blender
allocation or persistent lifecycle, so it needs no independent TLA+ scope.

It checks the exact material/parsed source/evaluator identity, selected pixel
binding, typed descriptor source/type/lanes/clamps, property index/storage/raw
program/default associations, and the complete native-order per-token evidence.
The existing numeric expression leaf supplies float32/clamp/fallback behavior.
Only all-four-context absence can select the captured stored property. It never
substitutes raw particle color, skipped contexts, white, zero, Age or replay time.

The caller still owns capture freshness, loaded modules/current draw binding,
both-target/full-CPU-cohort equality and frame-bound render GameTime. Private
DirectMaterialSource and the capture/window/monitor specs cover those owners.
This projection alone does not admit a model, a Blender graph or a scene export.

`bind_slide_frame_parameters` is another pure leaf. It accepts an explicit direct
draw vector query and independently captured scalar raw GameTime, requires exact
replicated finite binary32 equality and a complete lookup prefix, and exposes no
Age/tick/FPS time fallback. The caller's existing source/cohort/owner proof remains
mandatory; a matching float does not establish GPU submission or camera timing.
