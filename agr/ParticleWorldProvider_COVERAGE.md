# Unowned world provider

`ParticleWorldProvider` models the whole synchronous request/admission/package
boundary. The input Boolean interface is concretely checked by
`particle_world_origin.literal_birth`, C# `WorldOriginInputs.Qualify` and the
package validator. Request digest, response acknowledgement and original source
generation/range are revalidated before package publication. The adjacent
`ParticleWorldSelection` model covers the earlier generation fold/retention.

The model also covers the exclusive output-directory claim in
`recorded_world_effects.prepare_world_package`: an existing output is refused,
failure retains diagnostics, and a partial package write is not successful
publication. Helper freshness/request matching is its bounded interface; this
does not promise protection from malicious concurrent writes inside an owned
directory, atomic JSON writes or automatic recovery/cleanup. A stopped attempt
requires a new explicitly chosen output directory, never a retry over old data.

No new emitter, allocator, asynchronous job or native lifetime state is added.
The current world profile forbids DESTROY and later control changes; the existing
owned lifecycle does not qualify world stops. Native forwarding/CP/release
fixtures and actual helper results are separate evidence; they do not prove
Source spawn phase or Blender/projected rendering. Asset conversion and Blender
transaction/rollback retain their existing models and boundaries.

Simplification: use one immutable request header and a separate world package
backend. No dummy entity, mutable owner alias, extra lifetime scheduler or
changed owned request policy is needed. Acknowledgement remains explicit, and
the original world source is part of its own scene identity.

The b28 integration reuses only this narrow profile. Canonical JSON digest/SHA
validation in particle_value_identity is pure arithmetic/type checking, not a
cache or retained provider. The b28 owned asset preparation remains unchanged;
the exact five world definitions use its existing static texture adapter. The
current helper is compiled from b28 sources with the additive WorldOriginInputs
class; older broad research providers are not imported. Capture/extraction CLI,
owned responses and .crav schema are unchanged.

The 6861 update adds a stateless exact client/renderer-pair lookup. The request
and package identity carry the selected known client; the renderer hash is its
paired immutable qualification input. Existing 6860 package identities are
validated with their declared known profile, without querying installed files.
No new lifecycle/cache/retry state is introduced: validWorld in the adjacent
model abstracts the preflight conjunction. Cross-build pairs and unknown hashes
are negative tests; current and legacy helper headers are exercised separately.
Native instruction reanchoring/emulation is separate evidence and does not
establish live allocation, Source timing, map projection or lighting parity.
