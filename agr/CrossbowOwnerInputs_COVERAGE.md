`particle_crossbow_owner.py` is a stateless immutable observation binder. Its
producer owns acquisition, native module/reader qualification, coherent body and
child graph checks. Content hashes prevent stale reuse; they do not authenticate
an edited packet. The current profile is separate from every legacy client hash.

`CrossbowOwnerInputs.tla` composes bind/capture/request/response/load, including
source changes between stages and saved-rig recapture. It names the actual Python
and C# callers. SnapshotRuntimeInputs and the existing snapshot row/particle
models own complete bone frames, advance-before-query and compaction. Existing
package rollback owns all Blender data allocation; capture_points uses finally
to restore its borrowed scene frame. There is no new cache, clock, retry or game
launcher. The simpler combined owner/birth packet replaces separate legacy
birth/child transports for this narrow current profile, without admitting those
legacy profiles. Arithmetic, live acquisition and render output are numerical,
saved-scene and visual obligations outside this bounded model.

The simulation-only single-child position patch reuses the already modeled
child-local writer/descendant propagation. Its additional root-write telemetry
has `AuthoredRootPositionSummary.tla/.cfg/.mutants.json` beside the patched state
class, embedded in the same public patch: six states and two guard mutants.
The actual host oracle checks literal CP transforms, child/sibling isolation,
set-once/reset, external collisions and sticky missing-input history. It is not
a new qualification of every native setter mode. The complete Crossbow response
must declare authored CP3, no missing points and no authored root positions.
The portable package also retains its canonical executed request and checks its
snapshot frames/original events, then re-evaluates the saved rig before geometry
allocation. These are independent checks; a matching model header alone is
insufficient. The enclosing protocol model checks 172 states and eight mutants.

The normal preparation path is connected only with a caller-supplied current
capture. Regular exports without it refuse this instance. No automatic live
capture/UI option is added and source presence is not shipped Crossbow support.
The supplied-input path now has fresh normal exports at24/30/60FPS, independent
saved/rollback checks and a four-frame CPU Cycles sequence. Ordinary CLI/UI
availability remains incomplete; r10 stays the default-input milestone. These
checks do not establish continuous live child topology or native bone-cache
parity throughout the clip; snapshot frames are reconstructed from the recorded
rig and authored rest under the narrowly bound birth/provider profile.
