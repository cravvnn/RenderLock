# Retained slide owner-input binding

This immutable component has no cache, process, file writer, allocation owner,
retry or state across calls. It needs no separate lifecycle model. Existing
package admission/rollback models own the separate cohort renderer integration.
This binding component itself does not dispatch or allocate a slide renderer;
the qualified normal path is documented in `CapturedSlideRender_COVERAGE.md`.

The retained source fingerprint is frozen verbatim from the research pipeline,
including its projectile envelope, complete owner event history and file hashes.
It must still match the original fixed source identity. The generic current
scene fingerprint is unchanged. No old reference is rehashed to make it fit.

The fresh target must have the same demo, inclusive output range, 62-tick warmup,
world/owner basis and all 383 owner motion samples. Model, skeleton and evaluated
pose files must match the three pinned byte hashes. Authored constraint data and
preparation dependencies remain exact except one explicitly measured extractor
source-hash transition; its geometry and pose outputs were independently exact.
Both admitted presence envelopes cover every output tick; only the recovered
prefix differs. Warmup-only render metadata permits one measured opaque-white
expansion. Output render metadata cannot change. No alpha/mode/color is inferred
for captured particle arrays from that warmup metadata.

Captured arrays are complete measured outputs. They do not re-simulate unrelated
network particles/projectiles. Those inputs stay untouched and are bound into
the fresh target fingerprint where the current scene contract includes them;
their independent availability and renderer gates remain. This binding is not
an empty-capture proof, a root-lifetime rule, current native-reader qualification,
an authenticity guarantee, or a claim that captured arrays match a future game
run. Cohort, native, material, camera and saved-scene validation remain separate.
